core 更像是整个项目的基础设施层,放一些所有模块都会依赖的通用能力,
比如日志封装、自定义异常、统一响应格式、依赖注入、文件存储抽象等等。
如果某个类只服务于 Ingress,就应该放在 ingress 模块内部,不用一开始就抽到 core 里。
等发现它真的被 parser、dispatcher、retrieval 等多个模块共同使用时,再提取到 core,这样模块边界会更清晰
也更符合你现在想要保持轻量、职责明确的目标。




:core 的职责不是管理模块间的服务链路,而是提供模块共同依赖的基础能力。比如日志封装、配置读取、workspace 管理、统一异常、文件存储接口等等。业务链路本身,比如上传、解析、调度、检索,还是留在各自的业务模块里更合适。core 只提供这些模块都能用到的底层能力。这样职责边界更清晰,也符合你想要的轻量架构。




common 更偏工具函数,比如文件操作、哈希、时间处理这些通用工具;core 则是偏系统级能力,跟 BestRAG 这个项目相关,比如 workspace 管理、配置加载、日志、依赖注入等等。你现在目标是保持轻量,其实可以只用一个 core,把系统级能力放进去,工具函数放在 core里的 utils 里就够了。等以后规模变大,再把 common 拆出来也不迟。这样结构简单,也更
